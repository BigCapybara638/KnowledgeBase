# Проверка реализации

Дата: 2026-11-02. Проверки выполняются в управляемой облачной среде Linux, а не на серверах компании. Фактический бюджет общего Nginx и параметры диска/ОС целевого сервера нужно подтвердить при развёртывании.

## Завершённые функциональные проверки

- Генерация sqlc 1.30.0, сборка production-ресурсов, Go-бинарного файла и `go vet ./...` — успешно.
- 69 именованных Go-тестов, `go test -race ./...` — успешно. Проверяются реальные временные SQLite, PRAGMA на всех соединениях, миграции, FK, уникальность, конкурентные публикации, снимки ответов после commit, права на медиа, snapshot/restore и остановка HTTP.
- Восемь Playwright-сценариев — успешно: выдача учётной записи/смена временного пароля/блокировка; карточки/HTMX-меню/переименование с постоянной ссылкой/узкий экран; конфликт двух авторов; конфликт вкладок личного черновика; задержанное сохранение; задержанная публикация; изображения/таблицы с повторным открытием; кириллический поиск/архив/безопасные фрагменты.
- Docker-образ без CGO, отдельные runtime-процессы БД и Node.js отсутствуют. Production Compose ограничивает память до 768 МиБ без дополнительного swap, запускает приложение непривилегированно с read-only корнем.
- Интеграционный тест двух независимых Compose-проектов с настоящим HTTPS и доверенным тестовым сертификатом — успешно. Проверены существующий клиентский маршрут `app`, сохранность сессии/контента, запрет второго сервера над томом, намеренная смена IP приложения без перезапуска Nginx и клиента, SIGKILL/reopen, backup и фактический cgroup-лимит.
- Независимое ревью: три Important исправлены через RED → GREEN; подробности в [implementation-notes.md](implementation-notes.md). Непроверенных Critical/Important замечаний не осталось.

Для воспроизведения: собрать `knowledgebase:test`, затем `make test-capacity`. Короткий `python3 tests/load/capacity.py --seconds 15` — только smoke, не замена полных 10 минут. Результат сохраняется в `.validation/capacity.json`; контроллер не возвращает успех при раннем завершении, ошибках, OOM, неверном лимите или выходе за бюджет.

## Найденные и исправленные проблемы

Исходный Nginx с переменным `proxy_pass` без upstream-пула давал 502 примерно после исчерпания диапазона исходящих портов (`connect() failed (99: Address not available)`). Добавлены динамический `resolve`, общая upstream-zone и keepalive 64. Поэтому поставляемые примеры требуют Nginx 1.27.3+. Проверка специально удерживает старый IP приложения другим тестовым контейнером и требует восстановления маршрута через DNS.

Замечания независимого ревью закрыты тестами атомарного снимка результата, блокировки редактирования на время I/O и сохранения доступа к изображению через личный черновик. Ни ожидание HTTP, ни SQL-ошибка не заменялись ложным успешным ответом.

## Ограничения доказательств

Доступ к серверам компании, рабочему домену и TLS-сертификату не предоставлялся; публикация приложения туда не выполнялась. Процесс-крэш/SIGKILL не является испытанием отказа питания или диска. Перенос backup на независимый носитель — инфраструктурная операция.

Дополнительный `go mod tidy` блокируется сетевым доступом к test-only зависимости `goose` (архив modernc на Google CDN); это не зависимость runtime. Штатные build/vet/race/browser/Docker-проверки работают. TLS, npm integrity и Go checksum database не отключались. В сборке остаётся предупреждение upstream HTMX о наличии eval-кода; `allowEval=false`, `allowScriptTags=false`, CSP не разрешает `unsafe-eval`.
