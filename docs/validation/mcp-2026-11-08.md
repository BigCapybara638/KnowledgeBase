Go-проверки выполнялись в Linux Docker с Go 1.27.3. Для race-проверки
использовался отдельный тестовый образ с компилятором C. Браузер запускался
на Windows через установленный Edge. Тестовые БД создавались отдельно от
рабочих данных. Полный браузерный набор запускался на порту 4173, поскольку
существующие тесты используют этот адрес в дополнительных контекстах.

Готовый macOS-адаптер проверен сборкой; фактический запуск на macOS не проводился.
Нагрузочный сценарий на 5000 статей и все существующие разновидности MCP-клиентов
не проверялись. Совместимость ограничена описанными стандартными транспортами.

## Что проверено в авторизации

Хранение только SHA-256 хеша, принадлежность ключа, срок и отзыв, лимит 20
действующих ключей при конкурентном создании, обязательная смена пароля,
блокировка и отзыв при смене/сбросе пароля. Проверены CSRF и изоляция чужих
ключей в браузере. MCP не использует cookie как запасной способ входа.
Отозванный ключ отклоняется на следующем запросе уже подключённого клиента.

Поиск и чтение исключают неопубликованные и архивные статьи. Проверены
ограничения аргументов, Unicode-границы и полное восстановление текста из
нескольких частей, конкурентные клиенты с независимыми ключами, Origin,
отсутствие перенаправления с секретом и закрытие stdio.

## Независимый обзор и исправления

Отдельный проверяющий прочитал изменённые и новые файлы. Первоначальный
вердикт: Critical/Important не обнаружены, два замечания Minor; отказов
от оценки не было. Замечания проверены по фактическому влиянию:

1. Поиск без букв/цифр (`!!!`, emoji) раньше мог загружать 21 полный документ
   через прежний fallback поиска. Для ограниченного бюджета памяти это
   расценено как Important. Регрессионный тест сначала упал, после перевода
   всех запросов без поисковых слов на лёгкую выборку прошёл.
2. Добавлены недостающие проверки конкурентных клиентов, реконструкции Unicode
   и отмены активного stdio-вызова. Последняя выявила ожидание завершения
   отсоединённого SDK-обработчика при отмене процесса. Исходящий вызов теперь
   связан с жизненным циклом адаптера через `context.AfterFunc`. Тест отмены
   сначала упал, затем прошёл; закрытие stdin также проходит.

Отдельно до обзора исправлены обход ограничения длины строкой из пробелов
и скрытая на узком экране ссылка навигации. Для обоих воспроизведены падения
регрессионных тестов и последующее прохождение. После исправлений повторены
полный race-набор, vet, сборки адаптеров и production-образа, запуск Windows.
Отложенных замечаний нет.

## Решения разработчика

- Выполнение продолжено в текущей изолированной ветке после согласования
  варианта и ключей; повторное согласование плана не запрашивалось.
- Учёт прогресса велся в изолированном игнорируемом каталоге `.superpowers`
  напрямую, поскольку рабочая среда Windows, а вспомогательные скрипты POSIX.
- История ключей ограничена 100 строками, действующие показываются первыми:
  все разрешённые 20 активных ключей доступны для отзыва. Более старая история
  может не отображаться.
- Блокировка навсегда отзывает старые ключи, как существующие браузерные сессии;
  после разблокировки потребуются новые ключи.
- Пробелы/пунктуация/emoji без букв и цифр используют список последних статей,
  чтобы не загружать полные документы в выдачу.
- Пробелы проверок из плана доведены до покрытия перед завершением; обнаруженное
  зависание отмены исправлено. Отложенной проверки этих сценариев нет.

Рабочий экземпляр базы знаний и его данные не изменялись. Развёртывание
выполняется обычным обновлением контейнера по эксплуатационной инструкции.
