владельца ключа, ссылка на редактор, без публикации через MCP. Для ключа
необходимо явно разрешить создание черновиков на странице «Доступ агента».

## Обзор кода и исправление

Независимый проверяющий прочитал изменённые и новые файлы. Critical/Important
не обнаружены; одно Minor касалось подсказки адаптера после сетевой ошибки.
Отказов от оценки не было.

Для операции записи прежний совет «повторите запрос» признан ошибкой
поведения: ответ мог потеряться уже после сохранения. Добавлен тест,
в котором сервер выполняет запись и закрывает соединение до передачи ответа.
Сначала тест упал на прежней подсказке; после исправления прошёл. Теперь
адаптер сообщает о неопределённом результате и предлагает сначала проверить
«Мои черновики». Итоговый race-набор и vet пройдены после этого изменения.
Отложенных замечаний нет.

Первая попытка полного браузерного прогона выявила неточный локатор select
в новом тесте: проверка через роль combobox исправила тест. Изменять
производственную разметку ради локатора не потребовалось. После этого
отдельный новый сценарий и все 19 тестов прошли.

## Принятые детали

- Сохранение личным черновиком выбрано пользователем; остальные детали
  зафиксированы в [описании](../superpowers/specs/2026-11-11-mcp-article-drafts-design.md).
- Существующий ключ можно разрешить для черновиков через форму владельца,
  сохранив его секрет. Создание новых ключей по умолчанию остаётся только
  на чтение. Истёкшие/отозванные ключи изменение прав не оживляет.
- Вход — простой текст с сохранением строк; Markdown не интерпретируется.
  У инструмента честная аннотация non-idempotent: повтор создаёт новый черновик.
- Уже выполняющийся запрос может завершиться после отзыва, как в текущем
  контракте MCP; последующие запросы проверяют новые права.
- Сохранены ранее согласованные незакоммиченные изменения порта 8081.
  Работы выполнены в существующей изолированной ветке без повторного
  согласования уже выбранного пользователем создания черновиков.
