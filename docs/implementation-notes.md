# Решения реализации и независимая проверка

## Решения относительно исходного плана

- Служебные shell-helpers облачного skill были недоступны как ресурсы; этапы, тестовые журналы и commit ranges велись эквивалентным журналом. На приложение это не влияет.
- Драйвер SQLite — `github.com/ncruces/go-sqlite3` вместо `modernc`: официальный архив последнего перенаправлялся на закрытый CDN. Оба варианта не требуют CGO; используемый драйвер проверен Go checksum database. Стоимость выбора — другое поведение/производительность драйвера, поэтому отдельно проверены PRAGMA на всех соединениях, FTS5, конкурентность, snapshot/restore и нагрузка.
- Для одной статьи допускаются несколько личных черновиков. При конфликте новый создаётся отдельно, старый сохраняет текст. Цена — накопление черновиков; автоматическое удаление личной работы не выполняется.
- Compose-сервис называется `knowledgebase-app`, чтобы его автоматический DNS-алиас `app` не столкнулся с клиентским приложением в другом проекте. Команды эксплуатации используют это полное имя.
- Nginx-конфигурация использует динамическое разрешение upstream и keepalive, требует версии 1.27.3+. Исходный вариант с переменным `proxy_pass` в реальном длительном тесте исчерпывал исходящие порты (errno 99, ответы 502). Цена исправления — необходимость обновить более старый Nginx до применения примеров; реальные клиентские серверы автоматически не изменяются.

## Независимое ревью

Один независимый reviewer прочитал всю ветку от исходного README до реализации. Найдены три Important, Critical и Minor не отмечены. Исправления проверены воспроизведением RED → GREEN:

1. Ответ SaveDraft/Publish теперь содержит снимок, прочитанный внутри той же транзакции, а не состояние следующей записи. Тесты `TestSaveResponseKeepsItsOwnCommittedVersion`, `TestPublishResponseKeepsItsOwnCommittedVersion` детерминированно задерживают пул чтения и выполняют последующую запись.
2. На время save/publish блокируются текст, заголовок, категория, форматирование и загрузки. После неуспеха ввод восстанавливается. Браузерные тесты задерживают ответы сохранения и публикации и проверяют блокировку/возврат управления.
3. Изображение, на которое ссылается собственный сохранённый черновик, остаётся доступным владельцу этого черновика после удаления изображения из текущей публикации. Та же проверка применяется при сохранении ссылок. `TestDraftReferencePreservesAccessAfterPublishedImageRemoval` проверяет чтение и повторное сохранение; чужие несвязанные личные загрузки остаются закрытыми.

Повторное ревью тем же автором не выдаётся за независимое: исправления подтверждены регрессионными тестами и общей проверкой, без второго reviewer.

## Границы доказательств

Reviewer не оценивал результат параллельно готовившейся 600-секундной проверки — её фактические результаты вынесены в [validation.md](validation.md). Доступа к серверам компании не было: конфигурация и ресурсы реального хоста проверяются при развёртывании. Проверка SIGKILL подтверждает восстановление после падения процесса, а не fault injection отключения питания/отказа физического носителя; необходимы независимые резервные копии и надёжное хранение.

Обязательные сборка, генерация, vet, race-тесты, браузерные и Docker-проверки выполняются отдельно. Дополнительный `go mod tidy` в этой облачной сети блокируется архивом `modernc`, который импортируют **тесты зависимости goose**, а не наше приложение. Runtime и штатная Docker-сборка этого архива не требуют; отключение TLS/checksum-проверок не использовалось. Обычная среда с доступом к Go CDN может выполнить tidy.
