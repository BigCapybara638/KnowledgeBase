# Создание статей-черновиков через MCP

Дата: 2026-11-11. Пользователь попросил инструмент написания статьи и выбрал
сохранение как черновик.

Статус: реализовано и запущено локально на 8081;
[результаты проверки](../../validation/mcp-article-drafts-2026-11-11.md).

## Результат и рассмотренные варианты

Агент вызывает `create_article`, получает ID и ссылку на личный черновик
владельца MCP-ключа. Черновик открывается в существующем редакторе; пользователь
может проверить, оформить и опубликовать его обычным способом.

Рассмотрены создание личного черновика и немедленная публикация. Выбран
черновик: он соответствует текущему рабочему процессу и не появляется
в общем поиске до публикации. Изменение существующих статей и публикация
через MCP в эту задачу не входят.

## Предлагаемые детали реализации

- `create_article(title, body, category_id?)`: название и простой текст
  обязательны, категория необязательна. Название — до 512 байт, текст — до
  256 КиБ; некорректный UTF-8 и пустой текст отклоняются. Переносы строк
  сохраняются в документе редактора; Markdown не интерпретируется.
- Результат: `draft_id`, `article_id`, `title`, `version`, `status: draft`,
  абсолютный `edit_url` на `/drafts/{id}/edit`.
- Полный черновик создаётся одной транзакцией после проверки содержимого,
  пользователя и категории. Ошибка не оставляет пустую статью/черновик.
- Автор и владелец берутся из MCP-ключа, клиент не передаёт их в аргументах.
- Инструмент имеет `readOnlyHint: false`, `destructiveHint: false`,
  `idempotentHint: false`: повторный вызов создаёт новый черновик.
- Новое поле ключа `can_write` по умолчанию false. Существующие ключи сохраняют
  прежние права; их секреты не меняются. Права можно выбрать при создании
  или переключить у своего действующего ключа в браузере с CSRF-защитой.
- Для ключа только на чтение сервер перечисляет прежние четыре инструмента;
  `create_article` доступен ключам с разрешением на создание черновиков.
  Проверка ключа и прав выполняется на каждом HTTP-запросе. Уже выполняющийся
  запрос может завершиться после отзыва, как предусмотрено текущим контрактом.
- После изменения прав клиенту предлагается переподключить MCP, чтобы
  обновить список инструментов. Адаптер stdio передаёт инструмент и его
  аннотации так же, как существующие инструменты.
- Существующие незакоммиченные изменения порта 8081 сохраняются.

Это предложения разработчика для конкретизации выбранного пользователем
создания черновиков; формат входа и ограничения продолжают существующую
модель редактора и прав пользователей.

## Проверка

Проверить отсутствие изменений при неправильных данных, атомарное создание,
сохранение строк и кириллицы, владельца, необязательную/неверную категорию,
отсутствие статьи в поиске до публикации и возможность дальнейшей публикации
через существующий сервис. Проверить права ключей, отзыв, запрет чужого
переключения прав и CSRF. Пройти полный Go race-набор, vet, sqlc, сборку UI,
браузерный сценарий разрешения/создания/публикации, stdio и Docker-сборку.
