# Подключение агентов к базе знаний через MCP

MCP встроен в основное приложение и доступен по адресу
`https://<домен-базы>/mcp`. Отдельный сервер и копия SQLite на компьютере
сотрудника не нужны. По умолчанию ключ разрешает поиск и чтение опубликованных,
неархивных статей. Для нужных ключей можно отдельно разрешить создание личных
черновиков; проверка и публикация выполняются в редакторе на сайте.

## Создание ключа

1. Войдите на сайт базы знаний и откройте **Доступ агента** в верхнем меню.
2. Укажите название, например «Рабочий компьютер», и срок: 30, 90 или 365 дней.
   По умолчанию — 90 дней. Нажмите **Создать ключ**.
3. Скопируйте показанный ключ. Он начинается с `kb_mcp_` и показывается
   только в ответе на создание. Повторно получить его нельзя: создайте новый.
4. Сохраните ключ в локальной конфигурации/хранилище секретов агента.

У каждого сотрудника свои ключи, до 20 действующих одновременно. На странице
видны действующие ключи и история в пределах 100 записей, сначала действующие.
Нажатие **Отозвать** закрывает доступ со следующего запроса, даже для уже
подключённого агента. Выполняющийся запрос может завершиться.

Смена или сброс пароля отзывает все ключи. Блокировка пользователя также
отзывает его ключи; после разблокировки создайте новые. Выход из браузера
не отключает агента. До смены временного пароля доступ к статьям и ключам
закрыт.

## Разрешение на создание черновиков

При создании ключа выберите **Права ключа → Чтение и создание черновиков**.
Для уже настроенного ключа нажмите **Разрешить черновики** в его строке
на странице «Доступ агента». Секрет и настройки подключения менять не нужно.
Переподключите MCP в агенте, чтобы обновить его список инструментов.

Инструмент `create_article` сохраняет новый личный черновик от имени владельца
ключа и возвращает ссылку на редактор. Пример аргументов:

```json
{
  "title": "Как настроить рабочее место",
  "body": "Первый шаг.\n\nВторой шаг."
}
```

Необязательный `category_id` можно взять из `list_categories`; иначе выберите
категорию позже в редакторе. Название обязательно, до 512 байт UTF-8.
Передавайте ровно одно поле: `body` с обычным текстом или `document`
с документом редактора, каждое до 256 КиБ. В `body` переносы строк сохраняются,
а Markdown и HTML воспринимаются как обычный текст.

Результат содержит `draft_id`, `article_id`, `title`, `version`, `status: draft`
и `edit_url`. Черновик не появляется в общем поиске до публикации. Инструмент
не редактирует существующие статьи и не публикует их. Каждый повторный вызов
создаёт отдельный черновик: перед повтором после обрыва связи проверьте
«Мои черновики» на сайте.

Кнопка **Запретить черновики** возвращает ключу доступ только на чтение.
Изменение прав применяется к следующему запросу, включая запрос уже
подключённого клиента; выполняющийся запрос может завершиться. Права чужих,
истёкших или отозванных ключей менять нельзя. Существующие ключи после
обновления приложения сохраняют доступ только на чтение, пока владелец
не разрешит создание черновиков.

### Форматирование статьи

Для оформления передайте `document` в формате JSON редактора Tiptap.
Структура доступна агенту в схеме `create_article` через `tools/list`.
После обновления приложения переподключите MCP, чтобы клиент обновил схему.

```json
{
  "title": "Настройка рабочего места",
  "document": {
    "type": "doc",
    "content": [
      {"type": "heading", "attrs": {"level": 2}, "content": [
        {"type": "text", "text": "Первый запуск"}
      ]},
      {"type": "paragraph", "content": [
        {"type": "text", "text": "Важно: ", "marks": [{"type": "bold"}]},
        {"type": "text", "text": "проверьте настройки."}
      ]},
      {"type": "bulletList", "content": [
        {"type": "listItem", "content": [
          {"type": "paragraph", "content": [{"type": "text", "text": "Войдите в систему"}]}
        ]}
      ]}
    ]
  }
}
```

Поддерживаются заголовки 1–3, абзацы, перенос `hardBreak`, маркированные
и нумерованные списки, цитаты `blockquote`, блоки кода `codeBlock`, разделители
`horizontalRule` и простые таблицы. В `marks` текста доступны `bold`, `italic`,
`underline`, `strike`, `code`, `link` и `textStyle`. У ссылки задайте
`attrs.href` с http(s) или `/articles/<UUID>`; цвета текста и фона —
`attrs.color` / `attrs.backgroundColor` в формате `#RRGGBB` у `textStyle`.
Каждый тип выделения задаётся один раз; встроенный `code` используется
без других выделений на том же текстовом узле.
У ссылки можно задать `attrs.title` — текст подсказки.

Таблица: `table` → `tableRow` → `tableHeader` или `tableCell` → `paragraph`.
Все строки должны иметь одинаковое ненулевое число ячеек. Доступны
`align` (`left`, `center`, `right`), `backgroundColor`, `colwidth: [160]`
и `height` у ячейки. Объединение ячеек и вложенные таблицы не поддерживаются.
Списки содержат `listItem`, начинающийся с `paragraph`; у `orderedList`
можно задать `attrs.start`. В блоках кода — текст без `marks`.

Документ должен содержать непустой текст. Ограничения: 32 уровня вложенности
и 10000 узлов. Видео, изображения, вложения, HTML и неизвестные элементы
отклоняются целиком до создания черновика. Созданная статья открывается
в обычном редакторе с сохранённым оформлением; публикация остаётся ручной.

## Подключение по HTTP

Если клиент поддерживает **Streamable HTTP** и Bearer Token, укажите:

- URL: `https://<домен-базы>/mcp`;
- авторизация: `Bearer Token`, значение — ваш личный ключ;
- либо HTTP-заголовок `Authorization: Bearer <личный ключ>`.

Пример для клиента с полями `mcpServers`, `url`, `headers`:

```json
{
  "mcpServers": {
    "knowledgebase": {
      "url": "https://kb.example.com/mcp",
      "headers": {
        "Authorization": "Bearer <личный ключ>"
      }
    }
  }
}
```

Названия разделов зависят от клиента; используйте его форму настройки MCP.
Ключ передаётся только в заголовке, не в адресе. Браузерная cookie не заменяет
ключ. Автоматический OAuth-вход и прежний HTTP+SSE в этой версии не реализованы.
Согласование поддерживаемой версии MCP выполняет официальный Go SDK v1.8.0;
проверены текущая версия и `2025-11-25`.

## Подключение через локальную команду stdio

Для клиента, запускающего MCP как локальную программу, используйте `kb-mcp`.
Адаптер переводит stdio в тот же защищённый HTTP MCP. Он не открывает локальный
порт, не читает файлы базы и не требует установленного Go после сборки.

Пример конфигурации Windows:

```json
{
  "mcpServers": {
    "knowledgebase": {
      "command": "C:\\Tools\\kb-mcp.exe",
      "env": {
        "KB_MCP_URL": "https://kb.example.com/mcp",
        "KB_MCP_TOKEN": "<личный ключ>"
      }
    }
  }
}
```

На macOS/Linux замените `command` абсолютным путём к `kb-mcp`.
stdout адаптера содержит только MCP; сообщения об ошибках идут в stderr.
Адаптер не следует HTTP-редиректам: сразу указывайте окончательный адрес `/mcp`.
TLS проверяется обычным образом. HTTP допускается только для localhost/loopback
при локальной разработке.

### Сборка адаптера

Из исходников с Go версии проекта:

```sh
make build-mcp
```

Для других ОС из Linux/macOS:

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -o bin/kb-mcp-windows-amd64.exe ./cmd/kb-mcp
CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -trimpath -o bin/kb-mcp-darwin-arm64 ./cmd/kb-mcp
CGO_ENABLED=0 GOOS=darwin GOARCH=amd64 go build -trimpath -o bin/kb-mcp-darwin-amd64 ./cmd/kb-mcp
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o bin/kb-mcp-linux-amd64 ./cmd/kb-mcp
```

В Windows команды сборки можно выполнить в Go-контейнере с checkout,
смонтированным в `/workspace`; `go build` запускается внутри контейнера.
На компьютере сотрудника достаточно готового файла для его ОС/архитектуры.
Разместите бинарный файл в постоянной папке и настройте абсолютный путь.

## Инструменты

| Инструмент | Аргументы | Результат |
| --- | --- | --- |
| `search_articles` | `query`, необязательный `page` | До 20 совпадений с фрагментами и URL; `has_next` |
| `list_articles` | Необязательные `category_id`, `page` | До 20 карточек опубликованных статей; `has_next` |
| `get_article` | `id`, необязательные `offset`, `limit` | Текст, категория, авторы, версия, даты, URL и следующая позиция |
| `list_categories` | Необязательный `page` | До 100 категорий; `has_next` |
| `create_article` | `title`, ровно одно из `body`/`document`, необязательный `category_id` | Новый личный черновик и ссылка на редактор; требуется разрешение ключа |

Ключ только на чтение видит первые четыре инструмента. Ключ с разрешением
создавать черновики видит все пять; инструмент создания отмечен как операция
записи, чтобы клиент мог запросить её подтверждение.

Страницы начинаются с 1. Поисковая строка — максимум 256 символов; пустая
показывает последние статьи. FTS5 ищет слова по существующим правилам сайта,
без морфологического и векторного поиска.

`get_article` возвращает сохранённый простой текст. По умолчанию — 12000
Unicode-символов, максимум — 20000. Позиции считаются в символах, не байтах.
Если `next_offset` не равен `null`, вызовите инструмент ещё раз с этой позицией.
`total_characters` показывает полную длину. Запрос за концом текста возвращает
пустую часть и `next_offset: null`. Если статья меняется между запросами,
сравните `version` и начните чтение с начала.

HTML-оформление, структура таблиц, адреса ссылок и вложения, отсутствующие
в сохранённом простом тексте, не передаются. Исходная статья доступна по `url`
в браузере после обычного входа. Все результаты содержат структурированный
JSON и текстовое представление для разных MCP-клиентов.

## Эксплуатация и проверка

Обновите основной контейнер обычным способом. Новая миграция добавляет таблицу
хешей ключей; статьи и текущие сессии сохраняются. Данные ключей входят
в существующие резервные копии SQLite. Восстановление старой копии может
восстановить тогдашнее состояние ключей; после восстановления отзовите
неактуальные ключи, как и другие восстановленные учётные данные.

Используется текущий домен и существующий Nginx. Обычный `location /` из примера
проксирует `/mcp` вместе с Authorization; дополнительный порт не нужен.
Ответы не кешируются. Максимум тела MCP-запроса — 1 МиБ, обработка ограничена
15 секундами. Origin, если передан, должен совпадать с `KB_PUBLIC_URL`.

HTTP **401** означает отсутствие, ошибку, истечение или отзыв ключа, а также
блокировку пользователя/обязательную смену пароля. Проверьте, что клиент
передаёт Authorization. **403** при HTTP-подключении может означать неверный
Origin; **413** — превышение размера запроса. Для локальной разработки
используйте `KB_DEV=true` и loopback `KB_PUBLIC_URL`, как в основной инструкции.

Проверки реализации используют временные данные и не подключаются к рабочей БД:

```sh
go test ./internal/auth ./internal/mcpserver ./internal/mcpbridge ./internal/web ./cmd/kb-mcp
npm run test:e2e -- tests/e2e/mcp.spec.ts
```
